# Закрытие сессии

Быстро свернись, сохранив существенное. Это не аудит и не продолжение
незавершённого тикета; протоколы — context/workflow.md.

## Границы

- Пройди маршрут AGENTS/project/index/workflow/project-knowledge; прочитай
  spec-program, engine-facts, secrets и документы активного namespace.
- Документы открыты; в согласованном scope агент сам выравнивает проектные
  слои и ручной индекс. Обязательного librarian/CLI/ролевого брифинга нет.
- Не дописывай код, не закрывай цели за владельца, не выставляй verified:true
  без свежей проверки, не трогай git index. Не удаляй .work/, poc/, решённые
  цели и историю автоматически. Старый неразобранный handoff сохраняется.

## 1. Собрать состояние

```bash
git status --short
git diff --stat
git diff --cached --stat
```

Сверь context/main.md, context/views/goals.yaml и активные YAML-цели,
текущие изменения, .work/plan-review/, .work/review/ и .work/proofs/.
При сжатии контекста отметь ограниченную полноту и восстанови нужные документы.

## 2. Инвентаризация

Проверь восемь категорий незаписанного:

1. решение владельца, требующее записи в журнале;
2. факт движка с версией игры и доказательством;
3. наблюдение/дефект без цели;
4. устойчивая договорённость;
5. отброшенная альтернатива с причиной;
6. вопрос владельцу;
7. пруф без связи с критерием dod и пунктом плана;
8. красная проверка без разбора.

Пусто — всё равно выполни проверки.

## 3. Разложить результат

- Устойчивое → существующая entity/behavior/manual/convention/project или
  CHANGELOG по критерию журнала. Добавь evidence и обнови двусторонние связи,
  context/index.yml. Для engine-факта — версия игры и результат наблюдения.
  Отклонённые альтернативы не превращай в канон: ценную мотивацию принятого
  решения сожми в reason/журнал. Новое правило — только после согласования.
- Определённая оставшаяся работа → подходящая цель views, строка tasks
  нужного приоритета, критерии/чеклист в description; проверь goal-consistency.
  Не копируй очередь в handoff и не создавай новую цель без согласования.
- Остальное → context/main.md: дата, приоритет/блокер, что нужно и от кого,
  что известно, программа/цель и куда перенести после разрешения. Без dump
  канона, секретов и личных абсолютных путей. Снимать запись можно только
  вместе с переносом знания или явным решением об отмене её основания.

Перед итогом пройди путь следующего участника: AGENTS → context/index.yml →
нужный документ. Существенные правила, факты и решения должны читаться без
истории сессии или личной среды и переноситься с проектом, не оставаться
только в `.work/`, отчёте либо игнорируемой заметке.

Если запись вне согласованного scope — назови точный target и причину
ожидания; не выдавай предложенную правку за выполненную. Обязательные
результаты помощников принять и свести до итога по workflow, без polling.

## 4. Проверки

```bash
npm run check-secrets
npm run check-docs
```

check-secrets должен быть зелёным. При находке не объявляй завершение:
исправь в своём scope или передай владельцу; при утечке нужен отзыв секрета,
значение не показывай. Красный check-docs не запирает сессию: точная
диагностика, причина и следующий владелец — в handoff. Не заявляй PASS
при нулевом обходе старых путей. Ручной индекс обновляется в той же правке,
не требует ai CLI. Согласованные обычные ошибки исправляй сам.

## 5. Отчёт

Что записано и куда, что осталось, handoff (новые/старые записи, блокер),
результаты двух проверок и затронутые файлы. Если находок нет — три строки:
восемь категорий проверены, пусто, проверки и ограничения. Исход — по workflow;
«Готово» не маскирует обязательное продолжение или неполученный результат.
