# Открытие сессии

Дай владельцу короткий срез состояния, не начиная работу за него.

## Границы и маршрут

- Прочитай AGENTS.md → context/project.yml → context/index.yml →
  context/workflow.md → convention project-knowledge; затем spec-program и
  документы namespace задачи по индексу. Документы открыты агенту.
- Обязательных ролей, брифинга, bundles, ai/oc3 CLI нет. Процедуры хоста —
  `.agents/skills/`; не возвращай Claude-специфичные пути.
- Не ходи в сеть, не запускай полный npm run check, не выбирай тикет
  самостоятельно. Блокер handoff не даёт разрешения автоматически править файлы.

## 1. Handoff

Прочитай context/main.md. Непустой blocker разбирается до новой работы;
блокирующий вопрос предъяви по workflow, остальные записи учти в «первым».
Не теряй старые записи: снимать их можно после переноса знания в целевой
артефакт или явной отмены основания. Handoff — указатель на незавершённое,
не дубликат фактов и не журнал прогресса.

## 2. Собрать наблюдаемое

```bash
git status --short
git diff --stat
git diff --cached --stat
```

- Прочитай context/views/goals.yaml и релевантные program--/goal--*.yaml.
  Порядок в индексе и subgoals — приоритет, depends_on — зависимости;
  status — active/planned/paused, задачи — строки в priority sections tasks.
  Критерии dod и стадия — в description, не выводятся из названия файла.
- Последний plans/<key>/iter-NN.html: итерация, статус и горизонт по meta;
  расхождение с видимым текстом — находка.
- .work/plan-review/<key>/iter-NN--verify-MM.md: changes-requested блокирует
  вход в цели итерации. .work/review/<goal-key>/ — открытые раунды,
  .work/proofs/<program-key>/ — полученные/ожидаемые пруфы.
- Давность sync — context/project.yml. Старше 14 дней — предложи сверку
  одной строкой, не запускай source-sync сам.

Следующую цель предложи по spec-program: handoff и активная работа раньше
нового; затем готовые зависимости и порядок индекса. Не объявляй завершённым
то, что лишь отсутствует в старой очереди или не имеет доступного пруфа.

## 3. Быстрые проверки

```bash
npm run check-docs
npm run check-secrets
```

Красное покажи с сутью и указателем, не скрывай и не исправляй молча.
Проверь, что docs-check действительно обнаружил docs/context: зелёный нулевой
обход старой раскладки не PASS. Полные тесты/typecheck не входят в быстрый старт.

## 4. Сводка

Пустые блоки опускай, рабочие файлы дословно не пересказывай:

```text
handoff       <записи и блокер>
в разработке  <программа/цель, статус, итерация и горизонт>
можно взять   <готовая цель и почему она следующая>
незакончено   <стейдж ждёт /review, открытый раунд или пруф>
проверки      <check-docs, check-secrets, давность sync, ограничения>
первым        <одно предложение владельцу>
```

Чистое состояние — три-четыре строки. Пустые mods/ и poc/ при живой
PoC-итерации сами по себе не дефект. Выбор работы остаётся владельцу.
Заверши актуальным исходом по workflow, не начинай непорученную работу.
