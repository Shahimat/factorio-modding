1. Разбиение по goals

1.1 Каркас прототипа

Цель. Получить площадку, в которую складываются все остальные проверки.

Что делаем
пакет poc/shm-logistic-buildings-probe, консольную команду запуска проверок, единый формат строки отчёта
Что игнорируем
сами проверки механик, работу в mods/
№КритерийВидКак
1Исходники прототипа проходят линтер Luachecknpm run check-lua -- poc/shm-logistic-buildings-probe
2Прототип загружается в игре и команда отвечаетmanualЧто сделать: включить прототип в списке модов, запустить любую карту, выполнить в консоли /shm-probe. Что увидеть: ответ со списком доступных проверок и строкой версии. Что сообщить: «ответил» либо текст ошибки; factorio-current.log в пруфы цели

1.2 Стенд для тестов внутри игры

Цель. Перевести проверки из ручных в автоматические: дальше ответы даёт прогон, а не ваши глаза.

Что делаем
выбираем фреймворк из существующих (FactorioTest, FUnit, factestio) по двум условиям — работает на 2.0 и 2.1, запускается без графики; заводим команду запуска и демонстрационный сценарий, который ставит сущности и проверяет результат
Что игнорируем
сценарии под конкретные механики — они в 1.3–1.6
№КритерийВидКак
1Стенд запускается одной командой без графики и возвращает код ошибки при падении сценарияchecknpm run test:ingame
2Демонстрационный сценарий зелёный: сущности созданы, тики промотаны, результат сверенchecknpm run test:ingame
3Выбор фреймворка зафиксирован с отвергнутыми альтернативамиchecknpm run check-docs

1.3 Хранилища зданий и невидимый сундук

Цель. От ответов этой проверки зависят размер партии и сама возможность прятать сундук внутри здания.

Что делаем
сценарии стенда: сколько скрипт кладёт в хранилище машины за заход, при каком заполнении выхода машина встаёт, что с испорченным; невидимый сундук без коллизии в центре здания — обслуживается ли дронами, попадает ли в сеть, на что наводится манипулятор рядом у зданий 1×1, 2×2 и 3×3, принимает ли бур такой сундук целью сброса
Что игнорируем
создание и удаление сундуков по жизненному циклу здания
№КритерийВидКак
1Сценарии написаны, проходят линтер Luachecknpm run check-lua -- poc/shm-logistic-buildings-probe
2Сценарии зелёные на стенде, каждый печатает измеренное число или вердиктchecknpm run test:ingame
3Разбор вывода в сводку покрыт тестом на подставленных данныхunitnode tools/lua-test.ts ./poc/shm-logistic-buildings-probe

1.4 Запросы логистической сети

Цель. На чтении чужих запросов стоит весь расчёт спроса.

Что делаем
сценарии стенда: точки запроса сети и их содержимое вместе с количеством «в пути», признак буферного сундука, попадают ли в список персонажи, приходит ли событие при ручной смене запроса и при правке логистической группы
Что игнорируем
сам расчёт спроса и целей сети
№КритерийВидКак
1Сценарии написаны, проходят линтер Luachecknpm run check-lua -- poc/shm-logistic-buildings-probe
2Сценарии зелёные на стенде, буферный сундук отличён от обычного, событие пойманоchecknpm run test:ingame
3Разбор ответа сети в сводку покрыт тестомunitnode tools/lua-test.ts ./poc/shm-logistic-buildings-probe

1.5 Расходники и призраки запроса

Цель. Так доставляются топливо, патроны и семена — без этого половина зданий остаётся вне мода.

Что делаем
сценарии стенда: создание призрака запроса с указанием слота, дописывание своих строк в чужой призрак, несколько призраков на здании, чтение невыполненного остатка, запрос на изъятие отработанного топлива, снятие своих строк на работающем здании
Что игнорируем
переключатель способа доставки в интерфейсе; спам предупреждений — он проверяется глазами в 1.7
№КритерийВидКак
1Сценарии написаны, проходят линтер Luachecknpm run check-lua -- poc/shm-logistic-buildings-probe
2Сценарии зелёные на стенде, чужие строки призрака при дописывании целыchecknpm run test:ingame
3Сборка плана вставки для призрака покрыта тестомunitnode tools/lua-test.ts ./poc/shm-logistic-buildings-probe

1.6 Башня, шахта и панель у окна здания

Цель. Три возможности, которые либо есть в API, либо выпадают из мода.

Что делаем
сценарии стенда: хранилища семян и урожая сельскохозяйственной башни и определение продукта по семени, загрузка деталей ракеты и признак «ракета собрана»; пробную панель с привязкой к штатному окну для машин, печей, лабораторий, буров, котлов, реакторов и турелей
Что игнорируем
режимы работы башни и шахты, содержимое панели; внешний вид панели — он проверяется глазами в 1.7
№КритерийВидКак
1Сценарии написаны, проходят линтер Luachecknpm run check-lua -- poc/shm-logistic-buildings-probe
2Сценарии зелёные на стенде; привязка панели по каждому типу здания даёт «есть» или «нет»checknpm run test:ingame
3Сборка без Space Age не роняет прототип: башня и шахта пропускаютсяunitnode tools/lua-test.ts ./poc/shm-logistic-buildings-probe

1.7 Сеанс в игре и запись фактов

Цель. Закрыть то, что автоматика не видит, и превратить результаты в факты, на которые опирается следующая итерация.

Что делаем
прогон всего набора со Space Age, проверку глазами там, где стенд не отвечает — внешний вид панели и навязчивость предупреждений о нехватке материалов; запись фактов в namespace engine с версией игры и отличиями 2.1 по официальной документации; предложения обходов там, где механика не подтвердилась
Что игнорируем
правку дизайна мода — обход выбираете вы
№КритерийВидКак
1Весь набор прогнан со Space Age, вывод снятmanualЧто сделать: запустить карту со Space Age и прототипом, выполнить /shm-probe all, дождаться строки «готово». Что увидеть: по каждой проверке строку «имя — ок / нет — пояснение». Что сообщить: factorio-current.log в пруфы цели; если прогон оборвался — на какой проверке
2Панель и предупреждения оценены глазамиmanualЧто сделать: открыть сборочный автомат и печь; затем поставить десяток турелей без патронов в сети. Что увидеть: панель пристыкована сбоку и не перекрывает штатное окно; счётчик предупреждений о нехватке материалов. Что сообщить: два скриншота панели и число предупреждений одной строкой
3Факты записаны в namespace engine с версией игры, ссылки целыchecknpm run check-docs
4По каждой непройденной проверке есть предложенный обходcheckсверка отчёта с фактами: непройденных проверок без обхода нет

2. Допущения

  • проверяем на установленной 2.0.77; отличия 2.1 берём из официальной документации, клиент 2.1 для этой итерации не ставим;
  • подходящий фреймворк для стенда среди существующих есть; если ни один не пройдёт по двум условиям, 1.2 превращается в минимальный свой стенд и дорожает примерно вдвое.
